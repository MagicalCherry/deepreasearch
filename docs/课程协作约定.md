# MAS 实操课程协作约定

以下约定贯穿整个 MAS 实操课程：

1. 每次课程对话开始时，重新阅读 `MAS实操课程/AGENTS.md` 及 `MAS实操课程/01-项目任务书/` 中的业务背景、产品需求和验收标准；之后再按 tutor MCP 的当前步骤继续，避免脱离课程原则或沿用过期信息。
2. 帮助学员真正理解项目做了什么、具体怎么实现，以及为什么选择当前方案；解释要结合本项目和实际代码。
3. 采用数据驱动开发：从评测结果定位问题，围绕问题迭代，并记录改动、结果和取舍。
4. 每个 Sxx 阶段开始前，先根据 tutor MCP 当前教案列出本阶段各任务及内容。正式进入开发阶段后，每个新阶段完成时提醒学员在 VS Code 中提交并打 Git 标签。
5. 让学员亲手完成任务。需要运行命令时，提供适用于其系统的完整命令，引导学员在 VS Code 终端逐条运行，并等待其反馈结果后再继续。
6. 每次对话清楚说明本轮完成了什么、改动了哪些代码或文件、迭代依据是什么，以及学员接下来要亲自完成的操作。
7. 如果课程任务涉及网页显示或前端开发，以 `MAS实操课程/02-前端成品/` 的现有页面和组件为设计参考；沿用其视觉与交互，不自行另创设计。课程材料目录只读，只查看和参考，不直接修改。
8. 每次新建文件时，在文件开头添加注释，说明文件的用途、包含的内容及职责（例如函数、提示词、类或配置）。新建文件夹时，在对话中说明该文件夹通常存放什么内容；这项说明不写进注释。

## 课程执行边界

- 课程步骤和操作要求以 shenwei-tutor MCP 的当前教案为准；一次只推进当前步骤。
- `MAS实操课程/AGENTS.md` 与任务书是每次课程对话都要先复习的基础约束；尤其牢记材料只读、题集答案与证据编号隔离、不可联网搜题、不可读取或泄露 `.env`/密钥。
- 课程材料目录保持只读。
- 评测答案和证据文档编号只供评测程序使用，不进入 Agent 提示词、工具结果或检索请求。
- 不读取、打印或提交 `.env` 文件及任何密钥。
- 本项目按学员指定放在仓库根目录的 `Projects/` 下。
