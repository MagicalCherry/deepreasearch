## 系统完成后需要讨论的问题

1. BrowseComp-Plus 的固定通用网页评测，如何与电子通信行业的实际业务需求衔接？不能直接用通用基准成绩代替行业应用效果。
2. 行业网页从哪些来源采集，如何限定领域、时间范围、更新频率及资料覆盖？如何保存正文快照、发布时间、采集时间与历史版本？
3. 行业评测问题、标准答案和支持证据如何建立、审核与维护？如何隔离开发集与测试集，避免答案泄漏？
4. 更新资料后，哪些历史问题仍然有效？相对时间问题如何绑定明确截止日期？新证据、答案变化与旧证据失效如何处理？
5. 如何区分 Agent 改进与语料更新带来的变化？同一新版快照上是否需要同时重跑当前版本和候选版本，哪些基线需要重跑？
6. 在有限费用预算内，如何安排固定回归、近期问题抽查和发布前评测，避免每次资料更新都重跑所有历史版本？
7. 除精准问答外，如何评估完整报告的事实正确性、关键内容覆盖、引用支持、时间适用性及人工核查负担？
8. 最终简历如何准确区分已实现能力、通用基准结果、行业业务验证及尚未实施的计划？
