# v1.7阶段排查

## 范围与结论

运行s13-v17-qwen37-dev100-reuse20；最后一条结果为准，100题、14对、86错。只读结果、判分和开发集标注，标注仅用于命中数量统计；未联网搜题、未调用模型或检索服务、未修改Agent代码与原运行。可复算脚本scripts/diagnose_v17_stages.py，统计与原文件SHA256见v1.7阶段排查.json。

主要瓶颈在“规划产生可执行方向 → 检索命中 → 相关正文 → 有来源事实”的证据链；不能仅归责Scout，也不能说换一个大纲就能解决。Critic还存在核查结果严格适配及可观察性问题，Writer和最终抽取也有职责不一致现象。

## 86道错题的互斥分组

| 最早可观察的取证缺口 | 错题数 | 占86题 |
|---|---:|---:|
| 未返回任何标注证据 | 48 | 55.81% |
| 返回过标注证据，但未读其中任何一篇 | 24 | 27.91% |
| 已读过至少一篇标注证据，仍答错 | 14 | 16.28% |

前两组72/86=83.72%，说明应优先检查取证链。返回过指所有真实搜索响应，不等于Scout看到了该文档：RRF取前k、每轮最多12篇摘要都可能在模型看到之前筛掉文档。未读也可能由选择、去重、预算或停机导致，不能由计数直接归因为Scout拒读。

全100题：36题无事实，42题零阅读，以上均答错；所有14道正确题均有事实、正文阅读及来自标注证据的事实来源。但这只是相关关系，不证明“读任意一篇就能答对”。有16道错题也已从标注证据来源提取事实，仍需检查事实相关性、覆盖和推理。

## 1. Chief：大纲已不再固定行业报告，但规划仍有实际问题

58/100题的初始查询至少一条被clean_query拒绝，含53道错题、5道正确题。典型为[Game Name]、[Founder Name]、[Institution Name]等尚未消解占位符。不能把58题全部判作因占位符失败；当前Scout有初始查询修复，部分题也能答对。

第331题：原问题没有指定1980年，但第三个子任务已写成[Candidate Name] block success rate 1980 Olympics和[Candidate Name] volleyball statistics Moscow 1980。后续确有Tokyo 2020方向的搜索，说明并非永远被锁死，但规划已引入无依据的年份，增加绕路。

第590题：三个初始查询带占位符；“先找到创办人，再查其妻父、学校”等依赖却由并行章节启动。该题23次搜索、0次阅读、0条事实；查询修复未弥补证据链。当前三个Scout共享候选池，但已停止的章节不会仅因另一章节新找到候选而自动重新调度。

第422题：题目未明确学科和比赛类型，Chief查询已缩成chemist、Olympic athlete，随后实际扩写出现anabolic steroids、testosterone。假设用于探索可以，但不应变成唯一搜索方向。这是规划与检索改写共同造成的语义收窄，不能声称这些领域词来自已验证事实。

## 2. Scout与检索：搜索次数不少，相关材料进入正文和事实的比例低

平均36.58次实际搜索，但平均只读1.25篇，42题未读任何正文；因此瓶颈不是简单把并发调大或增加搜索次数。每查询扩写两条会共享50次预算，语义偏离也会被扩写放大。

第1177题：21次搜索、0读、0事实，检索曾返回1篇标注证据，未进入正文或事实。原问题说游戏director，实际扩写产生filmmaker founded company，把词义带向电影导演。记录证明语义漂移，不证明仅该次扩写导致全题失败。

第590题同样返回过1篇标注证据，但0读、0事实。第422题46次搜索、0读、7条事实、标注证据命中0，说明“有事实”也可能只是相关性不足的材料。

检索结果先经RRF保留前k，再进入最多12篇的260字摘要；read_docids最多2篇/轮、8篇/题，不是每篇都会读。当前没有强制“疑似直接答案文档必须先读”的机制；也未保存每次分析真正收到的完整输入清单及过滤原因，无法量化24题中多少是筛掉、未选、已读去重或预算问题。

本版全部实际搜索中中文检索数为0，先前“英文题被翻译成中文搜索”不是本批的主要问题。

## 3. Writer：有证据时仍可能在整题条件与直接答案间摇摆

第93题：37次搜索、3篇阅读、17条事实，返回全部4篇标注证据；Writer的best_answer依次Unknown → AdenoPlus → Unknown，最终抽取仍答对。说明不是所有失败或低验证比例都来自Scout。Writer会因部分背景约束未核实撤回候选，而独立最终抽取又从事实中提出候选，两者判断口径不一致。

第331题：40次搜索、2读、18条事实，返回5篇标注证据中的3篇、读2篇，但两次Writer均Unknown。审核意见认为已定位人物，却仍缺题目所求的具体统计值。不能据此断言Writer漏掉了已存在的数值；现有证据只支持“实体定位没有完成答案定位”。

原s4_port._extract仍要求不确定时给一个具体候选，Unknown还会触发第二次抽取。v1.7仅对置信度封顶，没有统一Writer、Critic和最终抽取对“允许给候选/应该弃答”的策略。此设计可能产生报告Unknown、最终具体答案；本轮不改动。

## 4. Critic：发现问题与解决问题是两回事，验证比例当前不能直接视为真值

89题最终verified=0，其中12题实际上答对。最后一次审核共727条条件，156条被适配代码归为通用的“Missing, ambiguous, or unsupported source check.”。正确14题的100条条件中有63条此类降级，不能把0验证直接解释为完全没有证据。

代码只接受整数constraint_index、逐字相同的constraint、唯一匹配项，以及来自已有事实且实际检索过的文档编号。编号类型、条件转述/标点、重复项或来源无效都会被保守降级；这是已确认的接口脆弱性。运行记录只保存降级后结果，没有原始constraint_checks，因此无法区分这156条的具体原因，也不能承诺放宽校验后分数会上升。应先记录原始返回、规范化结果及逐项降级原因，再据证据决定修复方式。

第93题审核摘要说已识别诊断设备，但最后10条条件均unverified，其中8条为通用降级；第972题最终答对，8条条件仍0验证、6条通用降级。这些是优先复核审核接口的具体案例，不是证明审核原判断全对。

64题stop_reason为no_new_evidence（其中58题错），29题search_budget，6题review_budget，1题completed。含义是系统大多因证据停滞或预算结束，而非核查通过。stop_reason可能优先保留之前的search_budget，不能当作互斥的根本失败原因。

## 5. 本批未再出现的旧流程缺陷

整题重启0题，末稿缺少后续审核0题。无新证据后停机是既有修复的行为；本批应改进停机前的检索和取证，而不是恢复无材料反复重写。没有根据把主要问题归为前端或运行错误。

## 建议排查/修复优先级（本轮未实现）

1. 审核可观察性：保存原始核查项与逐项降级原因；核查字段用稳定ID绑定，展示文本与匹配ID分开，不放宽真实来源约束。
2. 证据交接可观察性：记录RRF筛选、模型实际收到的docid、读文档选择与跳过原因，区分“搜到但没给Scout”和“Scout看到了没选”。
3. Chief查询及依赖：禁止初始未消解占位符；条件保持题意，新增年份/实体只能明确标为探索假设；找到实体后再启动依赖该实体的验证任务。
4. Scout取证：直接答案线索优先正文核查；已搜无事实时检查输入相关性及分析结构，再决定换方向、回读或终止。限制检索改写的语义漂移，不盲目扩大搜索预算。
5. Writer/最终作答：区分实体身份约束、背景约束与题目直接答案证据，统一候选与弃答策略，避免只改置信度却保留互相矛盾的作答决策。

这些变化会影响版本对照，应在学员确认后作为独立修复或对应下一阶段实现，不追改v1.7成绩，不自动重跑付费评测。

## 关于“置信度需要模型有依据地报”

有依据且保留评测是合理要求，但评测不要求置信度一定由模型口头生成；模型自报、验证比例、规则或校准映射都可对照真实正确率评估。本批已显示验证比例存在测量误差和稀疏样本，当前不能直接拿它取代概率。可保留模型原始自报值、依据、封顶后的值及实际正确性做对照；不能把“全部验证1/1”当作可靠概率估计。
